# Codex Project Instructions

## Working Style

- Prefer concise updates and avoid long explanations unless asked.
- Read only the files needed for the current task before editing.
- Summarize large files, logs, and command output instead of pasting everything.
- For simple changes, make the edit directly and report only what changed and how it was verified.
- For larger website work, first align on the smallest useful plan, then implement in focused steps.

## Website Planning

- Keep product, audience, content, brand, and maintenance decisions in `PROJECT_BRIEF.md`.
- Before adding new pages or sections, check the brief and existing patterns.
- Favor maintainable structure over one-off page code.
- Reuse existing components, layout conventions, colors, typography, and spacing once established.
- Avoid landing-page filler. Build the actual useful website experience first.

## Frontend Quality Bar

- Make the first viewport clearly communicate the site, product, venue, or service.
- Use real or generated visual assets where the site benefits from imagery.
- Keep interfaces responsive across mobile and desktop.
- Prevent text overflow, layout overlap, and unstable spacing.
- Use restrained, domain-appropriate visual design rather than generic gradients or decorative blobs.

## Maintenance

- Keep changes scoped to the requested feature or fix.
- Do not rewrite unrelated files.
- Add or update tests when behavior changes and the project has a test setup.
- After implementation, run the most relevant verification command available.
- Record durable project decisions in `PROJECT_BRIEF.md` so future work starts with context.
